# BERTech Materials: Semantic Supplier Matching System Architecture

This repository contains the complete system architecture, technical specifications, and business feasibility design for **BERTech Materials**, a platform designed to optimize B2B procurement for Moroccan SMEs/SMIs using Natural Language Processing.

The project delivers a comprehensive blueprint for replacing keyword-based searches with semantic similarity matching, bridging the gap between unstructured buyer inquiries and supplier catalogs.

---

## Project Genesis
This project was initiated as a product design and system architecture study for a technology-driven spin-off. 

To ensure the platform's viability, the architectural and business workflows were designed in collaboration with a partner NLP engineering team. This collaborative approach allowed us to translate core machine learning capabilities (such as semantic vector embeddings) into structured database schemas and user-focused B2B workflows, aligning technical specifications directly with market needs.

## System Architecture & Workflow

The platform is designed around a three-tier architecture connecting buyers (procurement teams) and suppliers:

1. **Client Tier:** Web and mobile portals tailored to specific user experiences (product upload for suppliers; search and request for buyers).
2. **Application Tier:** An API server managing authorization, product validation pipelines, and routing queries to the NLP matching engine.
3. **Data Tier:** Relational SQL databases storing structured supplier metrics and product metadata.

### Data Workflows (Logigramme)

The system maps two primary workflows:

* **Supplier Onboarding:** Form submission $\rightarrow$ Account verification $\rightarrow$ Automated Quality Control (via AI verification) $\rightarrow$ Product listing approval.
* **Buyer Match Request:** Unstructured query input $\rightarrow$ NLP Vector Encoding $\rightarrow$ Cosine Similarity Search $\rightarrow$ Ranked results rendering.

## Algorithmic Matching Logic

Rather than matching literal strings, the core matching engine utilizes vector embeddings generated by a multilingual BERT (Bidirectional Encoder Representations from Transformers) model.

### 1. Pre-training Context

The model utilizes a bidirectional transformer architecture optimized by maximizing the marginal probability of masked tokens within a text corpus:

$$\max_{\mathcal{T}} \frac{1}{|\mathcal{T}|} \sum_{t=1}^{|\mathcal{T}|} \sum_{i=1}^{n_t} \log P(w_{t,i} \mid w_{t,<i}, w_{t,>i})$$

Where $w_{t,i}$ represents the target token, and $w_{t,<i}, w_{t,>i}$ denote the surrounding context.

### 2. Fine-Tuning & Semantic Vector Search

To perform a match:

1. The buyer's request ($X$) and the supplier's product description ($Y$) are encoded into dense vectors $E_X$ and $E_Y$ using the fine-tuned encoder model.
2. The semantic match score is calculated using **Cosine Similarity**:

$$\text{Similarity}(E_X, E_Y) = \frac{E_X \cdot E_Y}{\|E_X\| \cdot \|E_Y\|}$$

A configurable threshold is enforced to filter out low-confidence matches before returning ranked listings to the procurement team.
